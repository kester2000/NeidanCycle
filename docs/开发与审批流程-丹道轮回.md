## 1. 项目组织（多智能体分工）

| 角色 | 职责 | 关键产出 |
|---|---|---|
| **编排智能体（PM）** | 读两份规格文档拆任务、维护看板、发起闸门审批、汇总升级提案 | 任务看板、闸门申请单 |
| **玩法智能体** | Cocos Creator 工程、物理系统、玩法脚本 | 可运行工程、场景与脚本 |
| **数值智能体** | 药材/丹方/经济/道韵数据表 | `assets/config/*.json` |
| **美术智能体** | AI 生图、切图、风格统一处理 | `assets/resources/` 素材 |
| **QA 智能体** | 单元测试、模拟器/真机冒烟、性能与包体检查 | 测试报告 |
| **合规智能体** | 文案合规扫描、提审材料、平台政策跟踪 | 合规清单、提审包 |

**协作机制**：

- 看板：`docs/kanban.md`（任务 / 负责智能体 / 状态 / 验收标准）
- 审批日志：`docs/approvals.md`（所有闸门与升级裁决的留痕，模板见 §9）
- 任务交接：每个任务必须先写验收标准再动工；交接产物 = 代码/素材 + 自测记录

## 2. 技术架构决策（ADR，已冻结）

| ADR | 决策 | 理由 |
|---|---|---|
| ADR-001 | Cocos Creator 3.8.x LTS + TypeScript | 双端小游戏官方支持最佳、内置 Box2D、可视化编辑利于多智能体协作 |
| ADR-002 | 无后端 MVP | 本地存档（`sys.localStorage`，JSON + 版本号字段），零运维零成本，验证期足够 |
| ADR-003 | 物理 = Box2D 刚体 + 参数化伪物理混合 | 药材/研杵/丹丸用刚体，药液/火焰用粒子伪物理，兼顾手感与性能 |
| ADR-004 | 双端适配层 `PlatformAdapter` | 统一接口 `showRewardedAd / share / showToast / reportAnalytics`，`tt.*` 与 `wx.*` 双实现，业务代码禁止直调平台 API |
| ADR-005 | 防作弊策略 = 接受风险 | 个人主体+验证优先，存档明文+版本迁移字段；后续版本再考虑存档混淆/服务端校验 |

**架构图**：

```
[业务层] 炼丹玩法 / 轮回系统 / 经济图鉴 / 引导
      ↓ 仅依赖
[系统层] 存档管理 / 数值配置加载 / 广告管理 / 音效
      ↓ 仅依赖
[适配层] PlatformAdapter（tt 实现 | wx 实现）
[引擎层] Cocos Creator + Box2D + 粒子系统
```

## 3. 里程碑闸门（五闸门制）

> 闸门 = 智能体完成准入条件后**停下等待用户审批**，用户批准前不得进入下一阶段。闸门之间自主推进。

### M1 规格冻结（当前所在）
- **产出**：GDD v0.1 + 本文档 v0.1
- **用户审批清单**：① GDD 玩法设计是否符合想象 ② 数值框架与内容量级是否认可 ③ 五闸门流程与合规方案是否认可
- **准出**：用户批准 → 两份文档标记"已冻结"，版本升 v1.0

### M2 可玩原型（灰盒，无美术）
- **产出**：研磨/投炉/控火/搅拌四步可玩的原型工程，抖音开发者工具模拟器可运行
- **用户审批清单**：亲自试玩 ≥5 分钟——手感"对不对味"（指跟手延迟、画圈判定、火候节奏）
- **准出**：手感认可 → 进入量产；不认可 → 迭代调参（此闸门允许 2–3 轮手感迭代）

### M3 内容量产完成
- **产出**：数值表全部填充（10 药材/8 丹方/经济/道韵）、42 张 AI 素材入库
- **用户审批清单**：抽查数值合理性（尤其利差与道韵定价）；素材风格统一度整体过目
- **准出**：数值与美术双认可

### M4 真机集成完毕
- **产出**：完整一世真机可玩、激励视频真机出量、主包体积 < 4MB、加载首屏 < 5s（中端机）
- **用户审批清单**：自己的手机实际试玩完整一世 + 触发一次真实广告
- **准出**：真机体验认可 → 冻结提审版本

### M5 提审前终审
- **产出**：合规清单全绿（§6）、资质材料齐全（§5.1）、提审包
- **用户审批清单**：最终批准提交抖音审核
- **准出**：提审 → 进入审核流程（§5.4）

### 3.4 规格偏离升级流程（闸门之间生效）

**定义**：任何与两份冻结文档不一致的实现改动 = 规格偏离。

```
执行智能体发现需偏离 → 记录提案至 docs/approvals.md（偏离点/原因/影响面）
  → 编排智能体汇总评级（轻微/重大）
    → 重大（影响玩法/经济/合规/体验）：暂停相关任务，等用户裁决
    → 轻微（纯实现细节，文档未约定）：自主决策，日志留痕，闸门汇报
  → 裁决结果回写文档（版本号 +1 小版本）
```

## 4. 工程规范

- **目录结构**：`assets/scripts/{core, systems, platform, ui}`、`assets/config/`（数值表）、`assets/resources/`（素材）；**元素地图引擎** `assets/scripts/core/ElixirMap.ts`（每世地图种子生成+可达性校验、药材路径曲线插值、穿越判定、元素量结算，纯函数无副作用，单测覆盖 ≥ 95%；**生成器可达性校验是首要任务**——任何生成地图必须保证全部丹方可达）
- **Git**：`main` 受保护；功能分支 `feat/*`、修复 `fix/*`；commit 格式 `type(scope): 描述`；分支由**另一智能体交叉评审**后由编排智能体合入
- **代码规范**：TS strict；物理/数值参数一律进 `config`，禁止硬编码；平台 API 只许出现在 `platform/` 目录
- **测试**：核心逻辑单测（**地图生成可达性校验、路径插值、穿越判定、元素量结算、品级计算**、丹毒累积、道韵结算、存档版本迁移）覆盖率 ≥ 80%；每个闸门前跑冒烟清单；M2/M4 真机覆盖高/中/低三档机型

## 5. 发布流程（抖音首发）

### 5.1 资质与账号（⚠️ 关键路径，M2 期间即启动）

| 事项 | 说明 | 周期 |
|---|---|---|
| 抖音个人开发者账号 | 注册 + 实名认证 | 1–3 天 |
| **软著申请** | 计算机软件著作权登记证书，个人可办；普通通道慢，建议加急代办（数百元） | 加急约 2 周 / 普通 1–2 月 |
| 小程序 ICP 备案 | 2023 年起所有小程序必需 | 1–2 周 |
| 小游戏备案 | 按平台最新要求执行 | 合规智能体于 M5 前 2 周核查最新政策并出清单 |

### 5.2 ⚠️ 重大前置风险：微信端主体门槛

**微信小游戏不接受个人主体**。微信移植（V1.2）需先注册个体工商户/公司主体。

**决策**：抖音首发验证数据 → 数据达标（§7 阈值）→ 再决定是否注册主体上微信。此项列入 V1.2 前置条件，不阻塞 MVP。

### 5.3 提审 Checklist（合规智能体产出，M5 提交）

- 类目：游戏 - 休闲益智（个人主体可选类目）
- 内容自检表全绿（§6 合规红线逐项）
- 激励视频广告位配置正确、奖励发放逻辑实测
- 隐私协议文本 + 权限声明（最小权限，仅激励视频所需）
- 测试说明 + 演示视频（如平台要求）

### 5.4 审核驳回应对

- 预期 1–2 轮驳回为正常范围；常见驳回：内容表述、素材疑似侵权、广告诱导、资质缺失
- 流程：驳回原因分析 → 修改 → 合规智能体复检 → 用户确认 → 重新提审
- 每轮驳回记录至 `docs/approvals.md`

## 6. 合规红线清单

| 类别 | 红线 | 执行话术/做法 |
|---|---|---|
| 题材 | 不出现现实宗教经文、神职、场所 | 架空修仙世界观；"轮回/渡劫/炼丹"为架空修仙通用词可用；禁用"六道轮回/超度/亡魂/开光/符咒治病"等宗教术语 |
| 迷信 | 无占卜、风水改运暗示 | 丹药效果只作用于游戏内数值，文案不出现"转运/消灾" |
| 广告 | 激励视频必须用户主动触发；奖励必发放；无误导按钮；遵守频控 | 4 个广告点位全部符合（GDD§6） |
| 未成年人 | 接入平台侧防沉迷；不诱导未成年观看广告 | 使用平台默认能力，不做年龄放宽 |
| 隐私 | 最小权限；无后端不采集个人信息 | 隐私协议写明仅本地存储；权限声明仅列激励视频必需项 |
| 知识产权 | 不使用 PotionCraft 任何素材/名称/文案；AI 素材确认生成工具条款允许商用 | 美术智能体保留生成记录备查 |

## 7. 数据验证方案（MVP 的存在目的）

- **数据来源**：抖音开发者后台自带看板（留存/时长/广告数据）。MVP 不自建埋点上报（无后端），自建事件统计列为 V1.1 事项
- **核心指标**：次留 / 三世率（完成 ≥3 世用户占比）/ 人均激励视频次数 / 平均单世时长
- **判定阈值**：
  - 次留 ≥ 30% 且三世率 ≥ 25% → 验证通过，启动 V1.1 内容扩展
  - 次留 15–30% → 优先优化手感与引导（结合 M2 手感反馈）
  - 次留 < 15% → 复盘核心假设，暂不追加内容投入
- **已知局限**：极小内容量会拉低留存绝对值；必须用"三世率"交叉判断——次留低但三世率高 → 内容量问题而非玩法问题
